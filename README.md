# SMB Mockup Framework

An on-demand, deterministic SMB sandbox for testing AI agents (CrewAI, LangGraph, MCP-based)
that interact with corporate file shares. Boot, seed, test, and self-destruct in a single
command. Perfect reproducibility for agent evaluation pipelines.

---

## Prerequisites

- Docker with Compose v2 (`docker compose` not `docker-compose`)
- Python 3.9+ with pip
- `make`

Install Python dependencies once:

```bash
pip install -r requirements.txt
```

---

## Quickstart (Profile 1 — Flat NAS)

```bash
cp .env.example .env
# Edit .env: set ADMIN_PASSWORD at minimum

make up           # Start containers, create bridge network
make seed         # Wait for healthy, create users, seed files
make creds        # Print seeded credentials to stdout
make probe        # Scripted pass/fail validation
make snapshot     # Save known-good state to snapshots/
make down         # Tear down and wipe all volumes
```

---

## Profiles

Select a profile with `PROFILE=<name>` on any make target. Default is `flat`.

| Profile | Command | What it simulates |
|---|---|---|
| `flat` | `make up PROFILE=flat` | Standalone workgroup NAS, local auth only |
| `standard` | `make up PROFILE=standard` | Samba AD domain controller + domain-joined fileserver |
| `secure` | _(deferred)_ | Segmented subnets per department, nftables router |

**Build order is enforced:** validate Profile 1 before building Profile 2, Profile 2 before Profile 3.

---

## All Make Targets

| Target | Description |
|---|---|
| `make up` | Start containers (creates bridge network if needed) |
| `make down` | Stop and wipe all containers and volumes (`-v`) |
| `make seed` | Wait for healthy → create users → seed file content |
| `make reset` | `down` + `up` + `seed` in one command |
| `make creds` | Print seeded credentials to stdout |
| `make probe` | Scripted validation — exits non-zero on any failure |
| `make snapshot` | Archive current volume state to `snapshots/` |
| `make restore` | Bring down, restore latest snapshot, bring back up |
| `make fault FAULT=<type>` | Inject a failure condition |

---

## Credentials

Credentials are generated fresh on each `make seed` run and written to `.generated-credentials`
(gitignored). Read them with:

```bash
make creds
# Output: username:password:department
```

Never hardcode these in agent repositories. Inject them at test time from `make creds` output.

---

## Snapshot / Restore Workflow

```bash
# Save a known-good seeded state
make snapshot PROFILE=flat

# Subsequent test runs: restore instead of re-seeding (much faster)
make restore PROFILE=flat
# ... run agent tests ...

# For a full reset:
make reset PROFILE=flat
```

`make restore` brings containers **down** before restoring volumes, then brings them back up.
Never restore while containers are running — Samba may have open file handles.

## Fault Injection

```bash
make fault FAULT=<type> [PROFILE=<profile>]
```

| Fault | Effect |
|---|---|
| `nas-down` | Pauses `samba-nas` — tests agent behaviour when NAS is unreachable |
| `nas-restore` | Unpauses `samba-nas` |
| `dc-down` | Pauses `samba-dc` — tests agent behaviour when domain controller is unreachable |
| `dc-restore` | Unpauses `samba-dc` |
| `acl-corrupt` | Sets `ledger_entries.csv` to `chmod 000` — tests unexpected permission denial |
| `acl-restore` | Restores `ledger_entries.csv` to `chmod 644` |
| `restore-all` | Unpauses all containers, restores ACLs — full reset between fault scenarios |

**Not implemented (v1):** network latency (`tc netem`), port blocking (`iptables`), clock skew.
These require `NET_ADMIN` capability or direct host NTP control and are deferred.

## Connecting Agent Repositories

1. Declare the shared bridge network as external in the agent repo's compose file:

   ```yaml
   networks:
     smb_test_bridge:
       external: true
       name: smb_test_bridge
   ```

2. Inject credentials from `make creds` at test time — never hardcode them.

3. Use `make restore PROFILE=<profile>` at the start of each test run rather than re-seeding.

4. Use `make fault` / `make fault FAULT=restore-all` to bracket fault-injection test cases.

## Seeded Content

| Share | Files | Purpose |
|---|---|---|
| `finance` | `ledger_entries.csv`, `balance_sheet.csv` | Structured financial data for read/query tests |
| `engineering` | `app.env` (fake secrets), `ADR-001-architecture.md` | Tests agent handling of sensitive-looking artifacts |
| `hr` | `review_<name>.txt`, `SOP-onboarding.txt` | Confidential free-text documents |

Content is synthetic (generated by Faker) and randomised on each seed. Files are never empty.

## Environment Variables

All configuration lives in `.env` (gitignored). Copy `.env.example` to get started.

| Variable | Used by | Notes |
|---|---|---|
| `DOMAIN` | profile-standard | NetBIOS domain name (e.g. `CORP`) |
| `DOMAIN_FQDN` | profile-standard | Full realm (e.g. `corp.internal`) |
| `ADMIN_PASSWORD` | profile-standard | DC admin password — must meet complexity requirements |
| `SHARE_FINANCE` | all | Finance share name (default: `finance`) |
| `SHARE_ENGINEERING` | all | Engineering share name |
| `SHARE_HR` | all | HR share name |
| `SMB_BRIDGE` | all | Docker network name (default: `smb_test_bridge`) |
| `SUBNET_FINANCE` | profile-secure | Finance subnet CIDR |
| `SUBNET_ENGINEERING` | profile-secure | Engineering subnet CIDR |
| `SAMBA_IMAGE` | all | Samba container image |

---

## Teardown

```bash
make down PROFILE=<profile>
```

Removes all containers and named volumes (`-v`). The bridge network is left in place — remove
it manually with `docker network rm smb_test_bridge` if needed.
